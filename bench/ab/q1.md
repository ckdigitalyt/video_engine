# Q1 acceptance: voice WER — metric audit + fix

Scope: owner decision #11, Q1 only (voice WER). No full video renders; all
numbers below are measured against **already-cached real beat audio**
(`stories/<id>/audio/beat_*.wav`, produced by earlier real renders — WP9's
`ice_slippery`, WP10's `tunguska_1908`, and other topic-pack renders) —
component-only, no new TTS synthesis or pipeline runs.

## 1. Metric audit (done before touching anything)

Code: `illustrated_engine/engine/voice/qa.py` (`round_trip`), `text.py`
(`norm_tokens`/`flat_tokens`/`edit_align`), `lexicon.py`, `align.py`
(`transcribe`). ASR model confirmed: **faster-whisper `base.en`**
(`configs/voice.yaml` `qa.asr_model`), CPU/int8, `beam_size=5`.

Both sides of the round trip go through the *same* `norm_tokens` normaliser
(lowercase, punctuation stripped, digits-as-words via `int_to_words`,
British/American spelling table, `%`→percent) — this part of the metric was
already symmetric and sound, confirmed by reading `flat_tokens` (used for
both `ref` and `hyp`) and by the existing `test_wer_gate_passes_spelling_and_digit_variants`
unit test. The gate also already has a lexicon `heard_as` mechanism built
for ASR-plausible-spelling-of-a-correct-read cases.

**Real bugs found by running the metric against real audio** (not visible
from a code-reading pass alone — WP10's own `bench/ab/wp10.md` names the
0.0542 number but doesn't audit why):

1. **Thousands-grouped numbers double-penalized.** faster-whisper sometimes
   writes a formatted number as two word-level tokens (`"2"` then `",000"`)
   instead of one `"2,000"` token. `norm_tokens` applied to the second
   fragment alone parses `"000"` as a standalone number and emits `"zero"`
   instead of completing `"two thousand"` — so a **perfectly correct**
   "two thousand square kilometres" was scored as hearing "two zero square
   kilometers", a real WER hit for a transcript that was actually right.
   Confirmed live: `stories/tunguska_1908/audio/beat_B1.wav` → ASR tokens
   `['2', ',000', 'square', ...]`.
2. **Ordinal suffixes never actually spoken/written as a separate token.**
   `norm_tokens("30th,")` expected the literal sub-token `"th"` to survive
   the round trip, but faster-whisper writes ordinals it hears back out as
   bare digits (`"30th"` heard → transcribed `"30,"`), so no real audio ever
   produces a matching `"th"` token on either a correct or incorrect read.
   This single-handedly held `beat_B1` well over budget even though the
   actual date ("June 30th, 1908") was read and heard correctly.

Both are genuine double-penalization of a correct transcript — metric bugs,
not narration defects — exactly the "digits-as-words vs digits" class the
audit was asked to check for.

**ASR model confirmed too weak for the 0.03 budget.** `base.en` hallucinated
on a real beat: `beat_B4` (`"Kulik's expedition..."`) came back as
`"coolix expedition ... no crater raider"` — a misheard name *and* an
inserted word that was never spoken. Re-running the identical wav through
`small.en` (already used elsewhere in this repo as the trusted/independent
timing estimator, see `bench/ab/wp3_voice_bench.py`'s `accept()`) transcribed
it perfectly (WER 0 vs 0.069). `base.en`'s own error rate was large enough on
its own to fail a correct narration; this is a measurement-apparatus choice,
not a pipeline/narration change.

## 2. Fixes made

| file | change | reason |
|---|---|---|
| `illustrated_engine/engine/voice/text.py` | `_NUM` regex now consumes a trailing ordinal suffix (`st/nd/rd/th`) and `_num_words` strips it before parsing, so `"30th"` normalises to `"thirty"` (matching how ASR actually writes ordinals back out) instead of `"thirty","th"` | bug 2 above |
| `illustrated_engine/engine/voice/text.py` | added `travelling`/`travelled` to the British/American `_SPELLING` table | found live on `tunguska_1908` `beat_B2` ("travelling" vs "traveling") — same bug class as the existing metre/litre/colour entries, just missing |
| `illustrated_engine/engine/voice/align.py` | new `_merge_number_fragments()` in `transcribe()`: glues a run of ASR word-tokens matching `digits` + `,ddd` (+ optional `.ddd`) back into one numeral token (with spanned timestamps) before anything normalises it | bug 1 above — also benefits caption timing (`align_to_script`), which shares the same token stream |
| `configs/voice.yaml` | `qa.asr_model: base.en` → `small.en` | ASR-model-too-weak finding above |
| `brand/ink_ember/lexicon.yaml` | added `airburst` (heard_as `"air burst"`), `barographs` (heard_as `"barrographs"`), `meltwater` (heard_as `"melt water"`) | real ASR-plausible-spelling misses found live on `tunguska_1908`/`ice_slippery`, using the lexicon mechanism exactly as designed (same pattern as the existing `betelgeuse`/`furcula`/`theropod` entries) |

No change to Kokoro synthesis, lexicon *phonemes*/*respell* (pronunciation),
pacing, or gaps — per the audit finding, the metric itself (wrong ASR model,
two tokenisation bugs) accounted for the measured 0.0542 WER on WP10's own
render; only 3 lexicon `heard_as` entries (the existing, designed mechanism
for this exact class of miss) were needed on top.

## 4. Known residual gaps (flagged, not fixed — out of Q1's 3-script scope)

Found while sanity-checking other cached stories beyond the 3 required for
the exit criterion — left alone, not cherry-picking the passing set to hide
them:
- `ice_slippery` `beat_B2`: "0.1" (a decimal, "zero point one degrees") —
  faster-whisper (even `small.en`) drops the word "point" and writes
  `"zero," "one"` with a 0.8s gap where it should be, a real ASR deletion,
  not a formatting quirk (ruled out: the gap is long enough to fit a spoken
  word). WER 0.0345, just over budget, after fixing the `meltwater`
  compound-word miss in the same beat.
- `baikal_deep`: `"Baikal"` (title toponym, not in lexicon),
  `"route"`→"root" (valid US homophone, not currently normalised as
  equivalent), and `"and"` dropped from "sixteen forty-two" — American
  number-reading convention, not a defect — stacked up to a few beats over
  0.03 on an otherwise-clean script.
- `tambora_1816`: similar one-off misses (`"Sumbawa:"`, `"tonnes"`,
  `"veil"`) in individual beats.

None of these are the double-penalization class the audit specifically
found and fixed (bugs 1/2 above); they're residual ASR noise / missing
lexicon entries on scripts outside this package's 3-script check. Worth a
follow-up pass if Q5's full-gate re-render needs more scripts to pass than
the 3 already proven here.
