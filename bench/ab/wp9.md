### Music-mood fit (A/B #4, owner judgement call noted)

`mystery` (Southern Gothic — dark, grooving, minor-key) for a "why is ice
slippery" physics explainer reads as a defensible but not obviously
"correct" pairing — the story's `function` mix happens to be
EXPLANATION-heavy (→ `calm` per-shot) but its `HOOK`/`CURIOSITY` shots
(→ `mystery`) win on raw screen time. This is the arc-weighting rule
working as designed (DESIGN §9: mood follows the dominant arc, not a
single "genre" label per topic) — flagging the specific pairing for an
owner listen (`~/phase4_out/wp9/final_ice_slippery_preview_8s.mp4`,
`sting.wav`) rather than asserting it is definitely the best choice; the 2
tracks/mood library is intentionally small and easy to extend once real
usage shows which pairings feel off.

## Deviations (flagged, not silent)

1. **Beat-snapped cuts are proven standalone, not wired into
   `v15_pipeline.run_pipeline`'s live cut placement.** Moving an
   already-decided shot boundary post hoc would cascade into re-timed
   captions and a re-render of that shot — a materially bigger, riskier
   change than this WP's scope (same reasoning WP7 used to defer
   `assign_templates`/`split_long_holds` wiring, and AGENTS.md's "grow in
   layers, never trade a working run for unfinished complexity"). The
   mechanism (`detect_beats`/`snap_cuts_to_beats`) is real, tested, and
   proven against real per-story cut/word data in
   `bench/ab/wp9_beat_snap.py`; 0/103 cuts snap with the pipeline's current
   *synthetic* WORDS_PER_SEC timing (expected — an unrelated tempo grid
   essentially never coincidentally lands within ±80 ms of a synthetic,
   perfectly regular word boundary). Real voice timing (already computed
   elsewhere in `v15_pipeline` via `v15_timing`) would very likely produce
   some real snaps; that wiring is left for whichever WP next touches live
   cut placement.
2. **No library `whoosh` file yet** — Kenney's CC0 packs (Impact/Interface/
   Sci-fi Sounds, all checked) don't have a clean "whoosh" hit; rather than
   force a poor-fit substitute, the existing procedural whoosh (a tested,
   working synth) stays the default for that one kind. Easy to add a real
   file + licence row later without any code change.
3. **Only 2 tracks per mood (10 total).** DESIGN §16's checklist suggested
   30–50 YouTube Audio Library tracks, but downloading from YTAL requires a
   signed-in YouTube/Google account — outside this run's "no account or
   payment" constraint. incompetech.com (Kevin MacLeod, CC BY 4.0) is
   directly downloadable with no account, has a public feel-tagged catalogue
   JSON, and explicitly permits monetised YouTube use with credit — used
   instead. The library loader itself places no limit on track count per
   mood; more can be added later (by either source) with no code change.
4. **Plate regeneration during the live-proof render (12 NVIDIA NIM calls,
   1 vision call) was NOT caused by WP9** — copying `build/v15/ice_slippery`
   into a fresh work dir did not carry over a matching scene-render cache
   entry (`render_index.json`'s content-hash keys didn't match), so scenes
   and their plates rebuilt from scratch. `bed_h` (the composite cache key
   WP9 extended) correctly triggered a composite rebuild for its own
   reasons too, but the plate/scene cache miss is pre-existing cache
   behaviour, not a WP9 side effect.

No fallback or retry path was removed or narrowed: the procedural
underscore/SFX synths are unchanged and remain the default whenever the
library has nothing for a mood/kind (regression-tested,
byte-identical output); the image-provider chain, TTS chain, gate
regeneration round and LLM adapter are all untouched.
