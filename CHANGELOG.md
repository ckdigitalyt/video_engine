## WP2 — Fail-closed QA
- Verdicts are now `PASS` / `HOLD` / `FAIL` (`v15_gate.verdict_of`): `FAIL` = a check ran and found a confirmed defect (`critical`), `HOLD` = a check could not run (`unverified`) or found a soft problem. Exit code of `v15_pipeline` and `v15_batch` is still "0 only on PASS".
- New gate check `plates`: plate QA must have RUN (`checked:true`; "plate QA did not run" = HOLD, also for `--no-plate-qa`), no plate may still fail it after regeneration (FAIL), regenerated plates must be re-checked (else HOLD), and the gate itself OCR-reads every plate used for provider stamps/domains, independent of the pipeline's QA path (a stamped plate = FAIL even if the vision call passed or was skipped).
- OCR pre-filter (`v15_plates.ocr_watermark`, tesseract CLI, no new dependency): reads only the bottom 10 % / top 7 % strips, hits only on known stamp tokens or a domain-like string (full-plate OCR of textured art is noise). Runs inside `plate_qa` before the vision call at no LLM cost, cached beside the plate as `.ocr.json`; hits fail the plate and trigger the existing regeneration round. Fixture: the Phase 2 blackhole "pollinations.ai" plate (`illustrated_engine/tests/fixtures/`).
- Judge: ONE critical frame fails (`text_garbled`, `text_unreadable`, `watermark`, `overlap`; V15 needed two). New issue codes `watermark`/`overlap` in the prompt and `llm/schemas/final_judge.json`. `empty_or_flat`/`subject_unrecognizable`/`too_dark` keep the two-frame rule (HOLD).
- New gate check `caption_safe` (ink bbox of every caption overlay inside the safe frame and clear of the right UI rail) and a right-rail rule in `text_bounds` (DESIGN §7: x>930 below y=760).
- Not done, deliberately: the file rename `v15_gate.py → v16_gate.py` / `v16_plates.py` (no reason to churn imports before the v16 pipeline exists); DESIGN §7's top-220 / bottom-1440 insets and the 84 px caption-size rule (they move with the layout in WP6/WP5); judge frame cadence 1 s/2 s (S11, later).
- No fallback or retry path was removed or narrowed: the plate regeneration round, provider chain and judge chain are untouched (the gate is stricter, not the recovery).
- Consequence to expect: V15's headline/label boxes are right-aligned to x≈1010 at y≈800, so every V15 render now HOLDs on `text_bounds` (right rail) until the WP6/WP7 layout changes.
