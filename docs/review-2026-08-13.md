## 1. Executive Summary

- **Two independent visualization pipelines coexist.** `mission_run.py` (legacy 16-stage runner, default of `tools/daily_video.sh`) builds visuals via `VisualDirector` → `src/assets/asset_router.py` + `stage_ai_imagery`; `mission_stills.py` (the **stills-first runner, which the daily cron switched to** — `logs/daily_cron_runner.log` shows `runner: stills` for 2026-08-11/12/13) builds visuals via `stage_stills_visuals()` → NASA/Wikimedia/AI stills + Ken Burns + a tiny Manim registry. They share script/voice/review stages but have **four separate AI-still implementations**.
- **Prompt lineage for AI stills is intact but leaky:** script LLM (`SCRIPT_PROMPT` at `mission_run.py:271`) → scene dicts (`search_queries`/`visual_goal`) → `_still_plan_for()` (`mission_stills.py:516`) → `_guarded_ai_prompt()` (`mission_stills.py:248`) → `_ai_still()` (`mission_stills.py:275`) → `NvidiaNimProvider.generate()` HTTP POST (`src/providers/image_gen.py:100-142`). **The script-authored `visual_goal` field is dropped** — the stills pipeline never reads it; it is re-derived by a second LLM call (`spec_builder._SPEC_PROMPT`, `src/verification/spec_builder.py:51`).
- **AI stills are exempt from the asset gate by construction** (`pre_verified = src in ("ai", "cached")`, `mission_stills.py:793`): they are never vision-verified at ingest, and the post-render `semantic_alignment` check skips them because `verification_passed=True` (`src/qa/jade_gates.py:323-329`). The single most-repeated review failure class (Venus female faces, man-with-microchip, city-lights-for-radar) lives entirely inside this exemption.
- **Unregistered topics get subject-less AI prompts.** `_detect_topic()` returns `""` for the five registered topics only (voyager/sun/pulsar/black_holes/moon, `src/director/visual_direction.py:71-89`); every real mission topic (Bloop, Wow! Signal, Venus, Upsweep, Slow Down, 52-Hz…) hits `f"{_detect_topic(text)} documentary scene, alternate angle N"` padding/coverage prompts (`mission_stills.py:705, 889`) producing **" documentary scene, alternate angle 2"** — no subject at all.
- **Dead/broken code is accumulating:** `src/workers/ai_image_worker.py` calls a nonexistent `generate_image()` method and is unreferenced; `src/v1/*` has zero importers; `src/assets/asset_intent_router.py`, `topic_classifier.py`, `asset_confidence.py`, `semantic_query_planner.py`, `visual_intent_planner.py` are unreachable outside the dead v1 wrappers; `mission_stills.AI_PROMPTS` (`mission_stills.py:323`) is unused; `src/orchestration/v2_pipeline.py` is test-only.

## 3. Answers to the Core Questions

### Q1 — WHO creates the visualization in the mission video pipeline?

The **operative (daily-cron) pipeline is `mission_stills.py`** (`tools/daily_video.sh:76-78`; `logs/daily_cron_runner.log` 2026-08-11/12/13 → `runner: stills`). Within it, **`stage_stills_visuals()` (`mission_stills.py:584`) is the single creator/assembler** of all visual assets; it is called exactly once, at `mission_stills.py:1922`. Per scene it produces, in priority order:

1. **Manim explanation clips** — *not created by the pipeline*: `_manim_scene_for()` (`mission_stills.py:658` → `visual_direction.py:112`) only **selects** pre-baked files from the `MANIM_SCENES` registry (`visual_direction.py:25-41`, files in `cache/manim/`, last written 2026-08-02..05 per `ls -la cache/manim`). Nothing in either runner re-renders them per episode; `ManimPlanner` (`src/manim/planner.py:192`) is only reachable through the legacy `ManimProvider` (`src/providers/manim_provider.py:81`), which matches a *different* topic vocabulary and looks for `cache/manim/<topic_key>.mp4` names that don't exist in the registry (`black_hole_geometry.mp4` vs actual `black_hole_lensing.mp4`).
2. **Vector beats** — `render_vector_beats()`/`vector_beat_for()` (`visual_direction.py:247,296`) are wired (`mission_stills.py:620,676`) but **no-op by design** (`FLAT_VECTOR_BEATS_ENABLED = False`, `visual_direction.py:208`; `GENERIC_MANIM_BEATS_ENABLED = False`, `:209`).
3. **Stills (the real workload)** — `_still_plan_for()` (`:516`) orders candidates; `_nasa_still_title()` (`:148`) and `_wikimedia_still_title()` (`:189`) fetch real photos; `_ai_still()` (`:275`) generates AI stills via NvidiaNim→Pollinations; `_kenburns()` (`:461`) renders each still into a 1920x1080 motion clip (zoompan, linear zoom, pan clamp). Coverage variants (`:865`), guaranteed fill (`:960`), and `_append_coverage_variant()` (`:1332`) also *generate fresh AI stills at render-plan time* (`_ai_still` at `:892`, `:994`, `:1376`).
4. **Ken Burns crops** — `_kenburns()` (`:461`) + border crop `_auto_crop_borders()` (`:341`) + mirror-band crop `_crop_mirror_bands()` (`:400`).

The **legacy `mission_run.py` pipeline** creates visuals differently: `stage_storyboard_and_direct()` (`mission_run.py:498`) → `VisualDirector.run()` (`src/director/director.py:139`) → `AssetRouter` (`director.py:25,91`; search at `:422`) → stock/NASA/Wikimedia providers (`src/providers/asset_provider.py`) + Manim/vector injection (`mission_run.py:542-601`) + `stage_ai_imagery()` (`mission_run.py:671`, hardcoded `AI_IMAGE_PROMPTS` `:622-633`) + heal-gen inside `_ensure_timeline_coverage()` (`mission_run.py:828`, AI gen `:859-909`). It does **not** call `stage_stills_visuals()`/`build_stills_timeline()` (verified: only `mission_stills.py:1922,2010` reference them).

## 4. Findings by Severity

### CRITICAL

**C-1. AI stills bypass the asset gate entirely — the exact failure class reviewers keep flagging.**
- **Location:** `mission_stills.py:793` (`pre_verified = fname in pinned or src in ("ai", "cached")`), gate call `:794-806`; downstream trust at `src/qa/jade_gates.py:323-329` (`if v.get("verification_passed"): continue`).
- **What's wrong:** Every AI still (and every cached still) is marked pre-verified and skips `AssetVerifier.verify()` — including the vision check (`asset_verifier.py:186-238`). The justification comment ("AI stills are generated FROM this scene's visual objective, so they are the safest assets by construction") only holds for the `visual_objective` plan entry; it is **false** for padding prompts (`:705`), coverage prompts (`:889`), fill prompts (`:1049`), and `_append_coverage_variant` prompts (`:1376`), which are generic "alternate angle" strings.
- **Why it matters:** Venus v3 reviews ("AI female faces 60-72s", "woman illustrations", "man-with-microchip 20s") — the open issue "3 critical asset replacements for mission/future scenes" (memory/2026-08-11.md:405) — are precisely the failures the gate exists to catch, but AI assets are exempted *by construction*. The post-render `semantic_alignment` gate then skips them too, so no automated check ever looks at an AI still's actual content.
- **Fix (no code edits here):** In `mission_stills.py:793`, drop `"ai"` from the pre-verified set and route AI stills through `verify_asset()` with `provider="ai"` and the AI-output-aware path — i.e. run the **vision check only** (metadata scoring is meaningless for generated images; give it a neutral score). Keep `"cached"` pre-verified only when the cached file was verified on a previous run of the *same* topic+script hash (manifest can prove it). Keep fail-open behavior when vision is down (`asset_verifier.py:218-238` already degrades gracefully).

**C-2. Unregistered topics → subject-less AI prompts (" documentary scene, alternate angle 2").**
- **Location:** `_detect_topic()` returns `""` for any text outside the 5 registered topics (`visual_direction.py:71-89`, `:103-109`); prompt builders at `mission_stills.py:705` (pad), `:889` (coverage), `:571` (no-spec branch `"Scene of {topic}"`).
- **What's wrong:** All mission topics in rotation (Bloop, 52-Hz Whale, Julia, Upsweep, Slow Down, Wow! Signal, Venus, Andromeda…) are unregistered, so padding/coverage prompts become `" documentary scene, alternate angle 1"` — the model receives **no subject**. The main-loop candidates (`search_queries`→NASA/Wiki, `visual_objective`→AI) still carry subject, so primary stills are fine; but every **coverage/fill variant** for these topics is subject-less, and these are exactly the shots that reviewers called wrong-subject.
- **Why it matters:** generates off-topic imagery on every non-registered-topic episode; also wastes two NASA/Wiki fetches per scene on empty-topic queries.
- **Fix:** add a `_subject_for(scene, text)` helper that returns `search_queries[0]` → `title` → first ~6 words of narration (strip stopwords) when `_detect_topic()` is `""`, and use it at `:571, :705, :889` (and `_append_coverage_variant` already uses `query_used` — make it prefer the same helper).

### MAJOR

**M-1. Four (actually five) divergent AI-still implementations.**
- **Location:** `mission_stills._ai_still` (`mission_stills.py:275`); `mission_run.stage_ai_imagery._gen` (`mission_run.py:685-696`); `mission_run._ensure_timeline_coverage._gen_still` (`mission_run.py:858-868`); `FallbackDirector._generate_ai_still` (`src/director/fallback_director.py:479-500`); `src/workers/ai_image_worker.py:34-58` (broken — calls `generate_image()`, which doesn't exist; `image_gen.py` only has `generate()`).
- **What's wrong:** Each copy has different guards/suffixes/dims/fallback order. The v25 session memory records an edit that "clobbered the try block in `_ai_still`'s provider loop" — direct evidence of the drift cost. `mission_run`'s copies lack the people-guard entirely; `fallback_director` reverses provider order (free Pollinations first).
- **Why it matters:** inconsistent prompt policy across runners; `mission_run` still ships un-guarded AI imagery if used; the worker is a landmine (AttributeError on first spawn).
- **Fix:** consolidate into `src/providers/image_gen.py` as `generate_still(prompt, out_path, *, scene_text=None, style_mod="", width=2560, height=1440)` (guard + style + circuit breaker inside), and make all five call sites use it. Delete `ai_image_worker.py` (or fix to call `generate()`).

**M-2. `_ai_still` re-guard loses scene context (and only "works" by accident).**
- **Location:** `mission_stills.py:282` — `prompt = _guarded_ai_prompt(prompt, prompt, "")`.
- **What's wrong:** The guard's people-exemption is decided against the **prompt string**, not the scene narration. Consequences: (a) a scene about a person whose prompt doesn't contain a people-regex word (e.g. a biographical scene whose `visual_objective` is "Jocelyn Bell Burnell at the Mullard telescope") gets `no people, no human faces` appended — the model then omits the subject person; (b) the double-guard at `_still_plan_for` + `_ai_still` is only prevented because the guard string itself contains "people"/"faces", which self-triggers `_PEOPLE_RE` (so the second application silently no-ops). Both behaviors are emergent, not designed.
- **Fix:** remove the re-guard at `:282` (guard once, in the caller, with the real `scene_text`); thread `scene_text` into `_ai_still()` if any call site needs it (e.g. `_append_coverage_variant` has `query_used` only — pass the scene narration there too).

**M-3. `_PEOPLE_RE` vocabulary is too narrow for person-centric science scenes.**
- **Location:** `mission_stills.py:245-247` — `astronaut|people|person|woman|man|crew|human|face|portrait`.
- **What's wrong:** "astronomer", "scientist", "engineer", "researcher", "discoverer", "physicist", "astronaut-candidate" etc. are absent. A scene narrating "astronomer Jocelyn Bell Burnell discovered…" gets the no-people guard appended → AI stills without the person.
- **Fix:** extend the regex with role words (`astronomer|scientist|engineer|researcher|physicist|discoverer|biologist|geologist|…`) — or better, invert: exempt people only when the scene has explicit person *subjects* from the EntitySpec (`spec.required_entities` matched against a person classifier).

**M-4. The script's curated `visual_goal` never reaches the stills planner.**
- **Location:** `_still_plan_for` (`mission_stills.py:516-583`) consumes `search_queries`, `spec.required_entities`, `spec.visual_objective` — never `scene["visual_goal"]`; `spec_builder._SPEC_PROMPT` (`spec_builder.py:51-86`) only sees narration+facts.
- **What's wrong:** the scriptwriter's explicit "what the viewer should see" is discarded, and a second LLM call re-derives a `visual_objective` from narration alone — duplicate cost (~5 extra LLM calls/run) *and* information loss (the script prompt's `visual_goal` is often more specific than narration).
- **Fix:** pass `visual_goal` into `build_spec()` and use it as the seed for `visual_objective` (LLM refines, doesn't invent); also add it as a fallback candidate in `_still_plan_for`.

**M-5. Cached-still reuse can resurrect wrong-subject assets across runs.**
- **Location:** `mission_stills.py:716-721` — any topic-cached file >15 KB is reused unless the scene's script hash changed (`fresh_scenes`, `:1905-1915`).
- **What's wrong:** an image that was *accepted* by a previous run (or pinned) but later flagged by reviewers (the Venus "man-with-microchip" was a real NASA asset) stays in `cache/stills/<slug>/` and is reused forever; `rejected_this_run` (`:642-655`) only protects within a single run, and the border/mirror/dedup gates don't check subject.
- **Fix:** keep a per-topic `rejected.json` (asset hash → reason) across runs; re-verify cached assets against the EntitySpec when vision is available (cheap: one call per cache hit); add a manual "blacklist asset" file for human-approved swaps.

### MINOR

- **m-1.** `mission_stills.AI_PROMPTS` (`mission_stills.py:323-335`) is dead — never referenced (grep confirms only the definition). Delete or wire into `_still_plan_for` as per-topic AI defaults.
- **m-2.** `src/assets/asset_intent_router.py`, `topic_classifier.py`, `asset_confidence.py`, `semantic_query_planner.py` (only re-exported by dead `src/v1/*`), `visual_intent_planner.py` (only `src/v1` wrapper + `tools/generate_v1_demo.py`) are unreachable from both production runners. `src/v1/*` has zero importers anywhere.
- **m-3.** `src/orchestration/v2_pipeline.py` is exercised only by `tests/test_v2_pipeline.py` — production-dead but kept as spec artifact.
- **m-4.** `NvidiaNimProvider` seed is time-based (`image_gen.py:110`) and never passed from the caller; `_ai_still` also never passes `seed` — combined with filename-based caching this is harmless, but deterministic seeds would enable A/B prompt comparisons.
- **m-5.** Circuit breaker (`mission_stills.py:269-273`) disables a provider for the *whole run* after 2 consecutive failures; a transient blip at the first still permanently degrades the run to Pollinations. Consider time-decayed failures instead.
- **m-6.** `_still_plan_for` dedupe (`:576-582`) compares exact tuples only; near-duplicate prompts (entity == query with different casing) can double-fetch.
- **m-7.** `est = max(4.0, len(text.split())/2.6)` (wpm assumptions at `:687, :863`) duplicates pacing logic that `src/cinematic/pacing_engine.py` / `_pace_pad_scenes` own; hardcoded 156 wpm can diverge from the actual TTS rate.
- **m-8.** No regression test covers `_still_plan_for` / `_guarded_ai_prompt` / `stage_stills_visuals` on an unregistered topic — the two Critical findings above would have been caught by such a test. Existing tests (v28–v32) are excellent at gate-level but none import `mission_stills` except `test_v30_provider_and_pacing_fixes.py`.

## 7. Risks & Open Questions

1. **Which runner is canonical?** Daily cron is `stills`; `tools/daily_video.sh` defaults to `run` (mission_run). A manual `daily_video.sh` invocation without `--runner stills` silently ships the legacy, un-guarded AI path. Decide and lock the default.
2. **Manim library is frozen and tiny.** All episodes reuse the same pre-baked `cache/manim` clips (last rendered 2026-08-05); unregistered topics get **zero animation** (`GENERIC_MANIM_BEATS_ENABLED=False`) — full-Ken-Burns videos. Is the "realistic direction" supposed to permanently eliminate animation for non-registered topics? If a clip is ever deleted, `manim_scene_for()` returns a stale path and validation (`mission_stills.py:661-671`) rejects it — no re-render exists in the pipeline.
3. **FLUX.1-dev prompt adherence for specific equipment** (spacecraft, landers, instruments) is the recurring failure (Venus probes → faces). NIM offers no negative prompt; consider (a) passing the EntitySpec `prohibited_entities` into the prompt text ("no people, no humans, no women, no men" verbatim), and (b) a **subject-relevance vision gate at ingest** as the real fix — P0 item 2.
4. **Vision model pinning:** `asset_verifier.py:81` defaults to `gemini-3.5-flash` (audit-verified working); other code paths still reference `gemini-2.5-flash` (quota-dead per 2026-08-11 audit). Sweep for remaining 2.5-flash references.
5. **NASA/Wikimedia fetchers** have no rate-limit/backoff handling; daily runs already depend on the topic cache. A 429 burst forces everything to AI (cost ↑, and C-1 makes those unverified).
6. **The "3 critical asset replacements" open issue** (memory/2026-08-11.md:405) maps exactly onto C-1 + C-2: it cannot be fixed by swapping 3 assets in `refine_stills`; it needs the ingest-side vision verification and subject-aware prompts so wrong-subject stills never enter the timeline in the first place.
7. **EntitySpec is an LLM dependency in the hot path**: `build_spec` runs per scene per run; if the cost-chain is down, `_from_keywords` (`spec_builder.py:154`) produces a weak spec and `_still_plan_for` degrades to topic-only AI prompts — combined with C-2 this is the worst-case failure mode for a fresh topic.
